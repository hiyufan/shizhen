# 抖音账号助手开发约定

本目录是 shizhen 仓库中的独立 Python 应用，继承根目录的代码风格、安全和提交约定。

- 安装包 `qiuyuantu-inbox`，模块 `qiuyuantu_inbox`，命令 `qiuyuantu-inbox` 与 `qiuyuantu-account`。
- 账号应用依赖核心 `qiuyuantu` 的解析器和转换工具；核心源码、Web 路由和默认镜像不依赖此应用。
- `src/`、`tests/`、`deploy/`、`docs/` 在本目录集中维护，不把账号实现重新移回主包。
- `README.md` 是主 README 内嵌内容的唯一来源；修改后运行 `python apps/douyin-inbox/scripts/sync_readme.py`，CI 用 `--check` 验证一致。
- 子项目离线测试命令为仓库根目录的 `python -m pytest -q apps/douyin-inbox/tests`；共用根 Ruff 配置，不能放宽质量阈值。
- 测试环境用 `--no-deps` 安装子项目，不引入浏览器运行依赖；实际账号使用独立虚拟环境安装全部依赖。
- 默认运行数据在 XDG 私有目录；保留 `PARSE_VIDEO_ACCOUNT_DIR` 和旧 `PARSE_VIDEO_DATA_DIR/accounts/douyin` 的优先级。迁移使用原账号目录，不重置游标、待选状态或去重记录。
- 页面内 `qiuyuantu.inbox.*` Symbol 是跨进程恢复的稳定协议标识，不随 Python 包名迁移改写。

- 普通抖音账号工具为 `src/qiuyuantu_inbox/account.py`，单次图集测试为 `src/qiuyuantu_inbox/reply_test.py`，持续工作流为 `src/qiuyuantu_inbox/`，操作见 [docs/operations.md](docs/operations.md)。账号会话独立存储，不与匿名解析器共享 Cookie；截图、浏览器控制和远程桌面入口不公开托管。单次测试和持续收发共用账号锁；持续回传必须显式传 `--send` 与收件范围。保留稳定账号 / 会话 ID 校验、持久去重、配额和发送前记录；未知送达结果必须人工核对，不自动重发。真实平台验证与离线队列测试分别报告。
- 作品实况逐项配对照片与视频，复用已登录网页的上传器与发送管理器；凭证和媒体加密字段不得导出页面。原生类型及照片 / 视频摘要必须同时匹配回执，缺失视频或客户端适配失败不能静默回传静态图片。手机保存是否为 LIVE 以接收方验证为准。
- 作品卡片可复用已登录客户端已经加载的公开媒体地址，必须校验原始消息、发送者、会话与作品 ID，禁止导出整份详情载荷或复用其认证字段。图片不使用带用户名水印的 `download_url_list`。未核实的单帧评论预览不能作为已完成的实况解析返回；原生相册实况回传成功不能当作评论卡片解析成功。
- 作品识别先检查本地有效产物，再只读客户端缓存，不为命中缓存等待界面锁或切换聊天；缓存读取独立校验登录账号和目标一对一会话，不依赖当前聊天或草稿。缺失或配对不全时保留串行补取与匿名解析回退。会话补扫按会话释放界面锁，数据库处理在锁外；只有完整扫描才推进对应游标，中断或未完成时保留补扫标记。
- 无水印评论实况必须来自原始图片与对应视频；平台保存后再转发的带水印文件不能代替解析结果，也不能引导用户用这条路径完成“求原图”。
- 单帧评论图片在准备完成后复核原评论，不能把收件瞬间尚未加载的详情当作实况视频缺失。优先读缓存，缺失时只查询目标评论；校验账号、发送者、会话、消息、作品与评论 ID，以及原始对象 URI。确认静态原图后正常回传；动态资源缺失、评论不可见和格式未核实分别提示，不能仅靠存在评论或单帧文件判定静态。
- 普通视频与完整实况先发送选择提示，按同会话、同发送者的文字回复回传原格式、GIF 或两者。实况的原格式为 LIVE，逐项保留照片 / 视频配对；多张图集只选一次，GIF 仅转换各实况配套视频。多条待选必须带编号，选择与过期状态持久化；不默认替用户选择，不重复发送已确认提示。GIF 按提示标明的前段时长限时、限像素和限体积转换，等待及回传期间保护原媒体与 GIF 缓存。
- 选择编号支持至少四位的唯一前缀，冲突时要求补全。多条待选时先发格式、再补编号也可选择；补编号状态绑定原会话、发送者、当时的候选和期限，成功选择即清除，不跨到后来作品。提示附作品标题；无有效格式上下文的裸编号不能默认回传。进度 / 取消仍使用完整八位编号。
- 原生相册实况只在选择 GIF 后提取视频，复用登录页面的请求管理器与实际加载的解码 worker。原消息的视频摘要对应原始加密文件，必须核对该文件；解码后的 MP4 单独记录缓存摘要。凭证、skey / tkey 及资源地址留在页面内，私有进程只接收有界媒体字节；取不到原始资源或摘要不符时停止，不能改用转码预览或其他视频。此能力不能当作评论卡片无水印实况解析成功。
- 多用户改造以 [账号工作流的扩展设计](docs/operations.md#多用户扩展实现与后续验收) 为设计基线：事件落盘与补扫、按用户分组及发送片段公平调度、账号浏览器单一所有者、共享素材任务和有界反压。已接入客户端事件、持久 DRR、先提示后按选择准备（原生流水线空闲时在等待选择期间预热原格式）、共享依赖及编号进度 / 取消；实施与多会话实测分阶段记录，设计讨论不自动扩大运行收件范围。
- 扩大试运行名单时核对稳定会话 ID、登录账号与发送者；新增会话使用独立收件基线，不重设全局基线，不补发历史请求或旧选择 / 控制指令，也不影响原会话的待选任务。
- 选择等待期间的原格式预热只预下载进共享缓存、在页面内预上传进资源缓存，不创建消息、不改任务状态，有正式准备或上传时让路；预热与正式上传在文件交给页面前共用作业数及源字节预算，正式排队优先。取消、超时或进程交接不能在实际传输结束前释放该预算；GIF 仍在选择后生成，可用 `PARSE_VIDEO_INBOX_CHOICE_WARMUP=false` 关闭。
- 事件绑定只传当前页面、所有者与代次校验后的唤醒提示，不传消息或凭证；消息仍经有界缓冲落盘后确认。阶段通知须在事务提交后发出，覆盖检查与等待之间的竞态并唤醒多个 worker；通知不能替代定时补查、重试期限或会话补扫。
- 原生发送流水线由 `PARSE_VIDEO_INBOX_NATIVE_PIPELINE` 明确启用；页面预上传不依赖当前聊天，凭证只留页面，持久计划只存句柄和客户端 ID。保持两路实际上传上限、字节反压和有界预取；SDK 实际提交启动后释放 UI，独立核对回执。原型包装必须限定 SDK 实例并验证安装成功；未知发送仍暂停核对，不能因回退重发。原生相册分享保留串行 GUI 回退；阶段指标逐消息存储，旧任务累计耗时不能当作消息 P95。
- 服务端接收成功不等于接收方可见；回执须检查页面内的回调状态、发送检查结果和仅发送方可见标记。明确受限时保存服务端记录、将片段与任务标成失败并暂停待核对，不自动重发或改格式绕过；不能只凭 `flightStatus=4`、`serverStatus=0` 宣称送达。
- 用户要求向其他用户开放时使用显式 `--all --send`，不再逐个维护名单。切换时保留原试运行会话的独立基线和未完成任务，其他会话从开放基线接收新请求；不把开放范围视为陌生人入口或多用户容量已经实测通过。
- 自动回关由 `PARSE_VIDEO_INBOX_AUTO_FOLLOW` 单独启用，仅与 `--all --send` 配合。首次完整扫描建立粉丝基线，启用后新增的稳定用户 ID 才进入独立有界队列；分页进度与发现记录在同一事务提交。关注请求前落盘、前后核验账号和双方关系，凭证留在页面；未知提交只查询、不自动重发，私密账号申请不等于互关成功。回关暂停和预算与媒体队列独立，仍共用浏览器单一写入所有者；显式回关暂停跨重启保留，不自动取关或补关历史粉丝。
- 用户指定的基线测试账号可单次入队补测，保留维护审计并走正常 worker；不能以此宣称新增用户的自动发现已经真实验收，也不能扩大为批量历史回关。
- 上传、提交和回执方案已实施，见 [实施记录](docs/operations.md#实施记录与开关)。真实平台实验与离线验证分开报告，未完成的持续高峰容量不能标记为已验收。
