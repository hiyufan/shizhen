# 最高画质与原文件核验

目标：所有已支持平台都取得最高画质或原画质；用户已明确本轮只处理免登录内容，因此核验范围是匿名可读取的最高档及公开原文件。登录、会员或购买后才可读取的专属资源不纳入本轮。当前仍在实施和验证，不能据此宣传全平台已经完成。

## 下载与预览

`video_url` 保持浏览器预览的语义。Web 解析结果新增 `download_format`，主下载按钮使用其中的直链或服务端下载选择器；较低档位继续留在菜单中。库调用方可用 `parser.quality.best_video_format()` 取得同一选择。音频、目录、不同构图的封面不参与视频档位比较。

档位按来源实际给出的分辨率、帧率、码率选择；不同编码的码率不能证明视觉质量相同，文件大小和 H.265 标签也不能证明它更清晰。解析器保留来源返回的编码选项。原尺寸、平台转码后的最高档、上传原文件需要分别核验，不能混用名称。

yt-dlp 清晰度列表使用实际返回的高度，不再封顶 2160p 或补出不存在的中间档位。下载选择器指定真实高度，同分辨率的高帧率分轨也可成为默认下载。原生 YouTube 下载若实际取得的高度与选择不符，报错而非把低档当成所选高清档交付。大小、超时和磁盘配额继续有效。

转换入口同样使用 `download_format` 中的高清源，包含服务端合并所需的 `format_spec`。已明确选档的准备请求不再为了适配体积而自动退档；超限或缺档时报告失败，未选档的兼容 API 调用保留原有优化默认。裁剪仍可使用解析时的兼容预览，但这个地址只留在浏览器，不发送给准备接口，不作为转换输入；预览失效时回退到已准备的本地文件。清空或换链接后，较早的准备结果不会再启动隐藏转换或替换新界面。
